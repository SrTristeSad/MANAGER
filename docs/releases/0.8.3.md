# MANAGER 0.8.3 — Scheduler / Drain / Failover

Data: 2026-10-11

A 0.8.3 fecha a primeira camada de decisão distribuída da Colmeia. O controlador passa a escolher o nó elegível para **novas alocações**, usando a saúde já autenticada da 0.8.2, sem entrar no caminho de dados VPN e sem assumir ainda a autoridade global de sessões.

## Scheduler

- contrato `manager-hive-scheduler-v1`;
- algoritmo `weighted-least-loaded`;
- carga baseada em sessões/capacidade/peso;
- RTT usado como componente secundário;
- desempate determinístico;
- somente nós enrolled, habilitados, `HEALTHY`, não drenados e com capacidade entram na seleção;
- filtros por protocolo, região, pool e escopo de `node_id`.

## Placement e CLI pública

Placement é administrado pelo controlador e permite alias amigável, país, região e pool por nó.

```bash
manager hive node status
manager hive node list
manager hive node show NODE
manager hive node placement NODE NAME COUNTRY REGION POOL
manager hive node select PROTOCOL [REGION] [POOL] [STICKY] [NODE_SCOPE]
```

## Sticky e failover

Uma chave sticky mantém afinidade com o nó anterior enquanto ele continuar elegível. Se o nó deixar de ser elegível por drain, health, capacidade, protocolo ou filtro, a seleção faz failover pelo mesmo algoritmo e atualiza a afinidade.

```text
selection_reason=sticky-eligible
selection_reason=sticky-failover
```

Esse failover é de **seleção para nova alocação**. A 0.8.3 não migra sessão VPN já estabelecida.

## Drain

```bash
manager hive node drain BR-SP-02 maintenance
manager hive node undrain BR-SP-02
```

Semântica:

```text
new_allocations_allowed=0
existing_sessions_terminated=0
```

O nó drenado deixa de receber novas alocações, mas sessões existentes continuam até encerrar normalmente.

## Auditoria e lifecycle

- audit JSONL registra placement, seleção, recusa, drain e undrain;
- scheduler não possui daemon próprio;
- uninstall normal preserva placement/sticky/audit;
- purge remove scheduler config, runtime sticky e audit;
- o helper temporário de integração foi removido do `main` depois da integração pública.

## Fronteiras da 0.8.3

```text
scheduler=weighted-least-loaded
sticky_session=1
drain_runtime=1
selection_failover=1
controller_in_user_vpn_path=0
global_lease_authority=0
global_max_sessions=0
global_accounting=0
```

A seleção de nó não substitui uma lease global. A próxima etapa, 0.8.4, será responsável por autoridade global de sessões, `max_sessions` global atômico e fencing distribuído.

## CI dedicado

O workflow `Hive Scheduler and Drain` cobre:

- contrato público `manager hive node ...`;
- placement e aliases;
- weighted least-loaded;
- sticky affinity;
- drain sem encerrar sessões existentes;
- sticky failover;
- health/protocolo/região/pool/node scope;
- audit;
- fronteira `global_lease_authority=0`;
- detach preservando estado;
- purge removendo estado/auditoria.
